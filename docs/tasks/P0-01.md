# P0-01: Scaffold the app and `npm run check`
Phase: 0   Owner: GPT1   Card by: setup (GPT2 to confirm)   Backlog: P0-01, X-13

## Goal
A clean, reproducible Electron + TypeScript (strict) project that opens a blank window, with one command that proves code quality. Everything later builds on this.

## Acceptance criteria
1. From a clean clone, `npm ci` succeeds with a committed lockfile.
2. Node version pinned in `.nvmrc` and `package.json` `engines`; Electron and all dev tools pinned to exact versions (no `^` or `~`).
3. `npm run check` runs Prettier (check mode), ESLint, `tsc --noEmit` with `strict: true`, and Vitest, and exits 0.
4. A deliberately badly formatted file or a type error makes `npm run check` exit non-zero (shown, then reverted).
5. `npm run dev` (or a scripted launch test) opens a blank window titled "Product Factory Console"; main window uses contextIsolation true, nodeIntegration false, sandbox true.
6. Folder layout matches PLAN section 6 (`src/main`, `src/preload`, `src/shell`, `src/engine`, `src/shared`, `tests/...`), with placeholder files only where needed.
7. Scripts `build`, `test:e2e`, `test:golden`, `package` exist (stubs allowed, each exits with a clear message).
8. `docs/DEPENDENCIES.md` lists every direct dependency with exact version, reason, licence, maintenance note and a lighter alternative.

## Failure cases that must be handled
- Type error and formatting error each fail the check (criterion 4).

## Out of scope / do not touch
Database, panes, UI beyond a blank window. Do not edit `docs/tasks/`, `tests/acceptance/`, `config/` values.

## Dependencies and assumptions
D-009 (Windows first), D-021 (Node LTS, Electron pinned).

## Test approach
Unit (Vitest sample test), scripted check run. Window launch: e2e or a main-process smoke test under xvfb in Linux; Windows launch listed NOT RUN until CI (P0-03) or Ashley's smoke test.
